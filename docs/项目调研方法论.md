## 核对清单（按顺序做，别跳）

### 第 1 步：摸清代码构成 —— "什么语言写的、多少行"

```bash
# 各语言文件数 + 行数（排除 node_modules/target/.git/dist）
python3 << 'EOF'
import pathlib, collections
EXCLUDE = {"node_modules","target",".git",".venv","dist","release","build",
           "__pycache__","rsshub","历史",".trash-作废文档",".pytest_cache"}
EXT = {".rs":"Rust",".py":"Python",".jsx":"React JSX",".js":"JavaScript",
       ".cjs":"Node CJS",".sh":"Shell",".css":"CSS",".ini":"INI"}
stat = collections.defaultdict(lambda: [0,0])
for p in pathlib.Path(".").rglob("*"):
    if not p.is_file() or any(x in p.parts for x in EXCLUDE): continue
    e = p.suffix.lower()
    if e not in EXT: continue
    n = len(p.read_text(encoding="utf-8", errors="replace").splitlines())
    stat[EXT[e]][0] += 1; stat[EXT[e]][1] += n
for lang,(f,l) in sorted(stat.items(), key=lambda x:-x[1][1]):
    print(f"{lang:<14}{f:>5} 文件 {l:>7} 行")
EOF

# 找"上帝文件"（单文件过大 = 该拆）
python3 -c "
import pathlib
for p in sorted(pathlib.Path('.').rglob('*.rs'), key=lambda p:-len(p.read_text(errors='replace').splitlines()))[:10]:
    if 'target' in p.parts or 'node_modules' in p.parts: continue
    print(len(p.read_text(errors='replace').splitlines()), p)
"
```

**判断标准**：单文件 > 1500 行 → 标记为"上帝文件"，考虑拆分。

### 第 3 步：三方覆盖对照 —— 找"有路无入口"和"命名不统一"

```bash
python3 << 'EOF'
import json, re, pathlib
mcp = {t['name'] for t in json.load(open('.神经总账/控制面.json'))['tools']}
src = pathlib.Path('zunzhe-core/src/cli.rs').read_text(encoding='utf-8')
body = src[src.index('enum Command {'):src.index('fn storage_paths_for')]
cli = {re.sub(r'(?<!^)(?=[A-Z])','-',m.group(1)).lower()
       for m in re.finditer(r'^\s{4}([A-Z][A-Za-z]+)\s*[{(]', body, re.M)}
app = pathlib.Path('desktop/src/App.jsx').read_text(encoding='utf-8')
fe  = set(re.findall(r"cli\(\s*'([^']+)'", app))
main = pathlib.Path('desktop/electron/main.cjs').read_text(encoding='utf-8')
wl = set(re.findall(r"'([a-z][a-z-]+)'",
         re.search(r'ALLOWED_CLI_COMMANDS = new Set\(\[(.*?)\]\)', main, re.S).group(1)))

print("【白名单有、前端无入口】", sorted(wl - fe))
print("【前端用了、白名单没有】", sorted(fe - wl))
print("【CLI 用 kebab / MCP 用 snake，顺序还相反】")
print("  CLI 独有:", sorted(cli - {m.replace('_','-') for m in mcp})[:12])
print("  MCP 独有:", sorted({m.replace('_','-') for m in mcp} - cli)[:12])
EOF
```

**判断标准**：
- 白名单有、前端无入口 → "有路无入口"（可能该加按钮，也可能该删命令）
- 命名不一致 → 逻辑问题，会让智能体调错

### 第 7 步：文档体量审计

```bash
python3 -c "
import pathlib
EX={'node_modules','.git','.venv','dist','release','target','历史','.pytest_cache'}
rows=[]
for p in pathlib.Path('.').rglob('*.md'):
    if any(x in p.parts for x in EX): continue
    rows.append((len(p.read_text(errors='replace').splitlines()), str(p)))
for n,f in sorted(rows, reverse=True):
    print(f'{n:>6}  {f}' + ('  ⚠️臃肿' if n>800 else ''))
"
```

**判断标准**：
- 单份 > 800 行 → 臃肿候选
- 检查标题编号是否**乱序**（曾发现 38/39/40 倒排）
- 检查 "最新/当前" 标记是否**泛滥失效**（曾发现 20+ 个"最新"）
- **设计 vs 流水账要分开**：如果一份文档里"设计"只占 3%，其余是"某天修了某 bug"，→ 该拆

### 第 8 步：构建与交付链

```bash
# 前端产物指纹（唯一可靠判据）
grep -oE "20[0-9]{2}/[0-9]{1,2}/[0-9]{1,2}[^\"']{0,20}" desktop/dist/assets/*.js

# app 内前端指纹
T=$(mktemp -d)
npx asar extract "/Applications/<App>.app/Contents/Resources/app.asar" "$T"
grep -oE "20[0-9]{2}/[0-9]{1,2}/[0-9]{1,2}[^\"']{0,20}" $T/dist/assets/*.js

# 签名与完整性
codesign --verify --verbose=2 "/Applications/<App>.app"
/usr/libexec/PlistBuddy -c 'Print :ElectronAsarIntegrity:Resources/app.asar:hash' \
  "/Applications/<App>.app/Contents/Info.plist"
shasum -a 256 "/Applications/<App>.app/Contents/Resources/app.asar"

# release 目录（是不是旧包）
ls -lat desktop/release/
```

**⚠️ 关键坑**：**不要用 grep 变量名对比前端版本**（`detailType` 等局部变量
minify 后会改名，两个版本都是 0 次）。**只有构建时间戳 `__APP_BUILD__` 能证明版本。**

## 判断"逻辑问题"而非"功能问题"的四个信号

| 信号 | 例子（本项目实测） |
|---|---|
| **同一件事有多套命名/实现** | CLI `add-live` / MCP `live_add` / 前端 `add-live` |
| **前端算的路径 ≠ 实际落盘路径** | `stash.js` 只用 `downloads`，漏了 `fupan_output` |
| **有通道但无入口 / 有入口但无通道** | 白名单 6 个命令前端不调用 |
| **失败不记录原因** | 21 个任务 `failed` 但 `last_error` 为空 |
