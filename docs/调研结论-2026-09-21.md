## 二、流水线源码实测（`fupan/pipeline.py`）

四步（第 105~140 行）：

| 步 | 动作 | 实现 | 产出 |
|---|---|---|---|
| 1/4 | **转写** | `transcribe.py`（本地 whisper） | `.转写.txt` + `.转写.json` |
| 2/4 | 知识提炼 | `distill.py` → 调外部大模型 | `.知识点.json` + `.复盘笔记.md` |
| 3/4 | 精华切片 | `clip.py`，依赖第2步 | `精华切片/` |
| 4/4 | 邮件通知 | `notify.py`，依赖第2步 | 邮件 |

**第 123~126 行**：

```python
if not distilled:
    summary['status'] = '未配置大模型接口，已保留转写文本，流水线结束'
    return summary        # ← 在这里直接返回
```

`distill.py:41` 要求 `[知识提炼] api地址` + `api密钥`，未配则返回 `None`
→ 流水线在 124 行结束 → **第3步切片、第4步邮件永远不执行**。

## 五、与用户口述的偏差对照

| 环节 | 用户要的 | 代码现状 | 判定 |
|---|---|---|---|
| 转文字 | 软件做 | `transcribe.py` 本地跑 | ✅ 一致 |
| 产物落盘 | 放该放的地方 | `<产物根>/fupan_output/{一级}/{二级}/` | ✅ 一致 |
| 智能体找产物 | 通过 MCP | `notes_list` 返回绝对路径 | ✅ 一致 |
| 知识提炼 | **智能体自带模型** | 软件要求自己配 API | ❌ **偏差** |
| 切片 / 邮件 | 应可独立触发 | 被第2步 `return` 卡死 | ❌ **偏差** |

**唯一需要改的**：软件不该把"智能体该干的第2步"设成流水线硬门槛。
**详见 `../项目宪法.md` 第 3 条。未获用户批准不动代码。**

## 六、环境坑（本轮实测）

- **本机没有 `timeout` 命令**（macOS 默认无 coreutils）
  → 调 MCP 用：`printf` 拼 jsonrpc 行 → 管道给 `zunzhe-core mcp` → `tail` + Python 解析
- `osascript ... Finder delete` 在**外置卷 A区**上失败（TCC -10004）
- `trash-put` / `gio` / `/usr/bin/trash` **都不存在** → 只能用 Python `unlink` 或 `mv`
