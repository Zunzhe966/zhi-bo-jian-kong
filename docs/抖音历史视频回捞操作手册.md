## 0. 一句话结论（为什么需要登录 cookie）

多轮实测（a_bogus 签名、本地开源工具、yt-dlp）均已证实：

> **抖音的用户作品列表接口 `aweme/post` 对"访客态"（无 cookie）返回空 body——无论是否带上 a_bogus 签名。当前 IP 环境连单视频 `detail` 接口也返回空。**
> 唯一可靠路径 = **登录态 cookie（含 sessionid）+ a_bogus 签名**，直接请求 `aweme/post` 分页拉取。

因此**批量回捞必须由你提供一次"登录抖音后的完整 Cookie"**。这是平台的硬门槛，不是技术没做到位。

## 1. 技术手段速览（为什么能跑通 / 边界在哪）

| 手段 | 作用 | 是否需要登录 |
|---|---|---|
| **a_bogus 签名**（`src/ab_sign.py`） | 过抖音接口签名校验（SM3国密+RC4+浏览器指纹），否则 403 | 否 |
| **完整浏览器指纹伪装**（UA/参数） | 降低风控识别 | 否 |
| **登录态 cookie（sessionid）** | 拿到用户作品列表数据的**关键凭证** | **是（必须）** |
| **yt-dlp 的 DouyinIE** | 仅支持单视频 `detail` 接口，**不支持用户主页批量拉取**；当前环境也要 fresh cookie | 单视频可免登录（理想），批量不行 |

**边界（重要）**：
- `aweme/post`（用户作品列表）→ **必须登录**。← 我们回捞用这个
- `aweme/detail`（单视频详情）→ 理论可免登录，但当前 IP 也被风控要 fresh cookie
- yt-dlp → 不支持主页批量，不是回捞答案

## 2. 操作流程

### 第 1 步：获取登录 Cookie（一次性，需你在浏览器操作）

1. 用浏览器登录 `https://www.douyin.com`（任意账号，能访问目标主页即可）
2. 按 `F12` 打开开发者工具 → `Network` 面板 → 刷新页面
3. 点任意一个 `www.douyin.com` 的请求 → `Request Headers` → 找到 **`Cookie:`** 整行
4. 复制整段 Cookie 内容（形如 `sessionid=xxx; ttwid=yyy; ...`）
5. 存成文件，例如 `config/douyin_cookie.txt`，或直接用 `--cookie` 传入

> ⚠️ 不要用访客 cookie，必须含 **`sessionid=`**（登录凭证）。
> ⚠️ Cookie 会过期，失效时重新执行本步。

### 第 2 步：先验证 cookie 是否有效（probe）

## 3. 命令行参数

| 参数 | 说明 |
|---|---|
| `sec_uid` | 目标用户 sec_uid（必填） |
| `--cookie "..."` | 直接传 cookie 字符串 |
| `--cookie-file 路径` | 从文件读 cookie（推荐） |
| `--max N` | 最多抓 N 条（默认全部） |
| `--count N` | 每页条数 1-18（默认 18） |
| `--download` | 拉取后下载无水印视频 |
| `--output 目录` | 输出目录（默认 `downloads/<sec_uid>`） |
| `--probe` | 只拉第 1 页验证 cookie 是否有效 |

## 5. 常见问题

**Q: 为什么 yt-dlp 下不了抖音？**
A: yt-dlp 的 DouyinIE 只支持单视频 `detail` 接口，不支持用户主页批量；且当前环境要求 fresh cookie（我们实测报错 `Fresh cookies (not necessarily logged in) are needed`）。

**Q: 为什么访客态拿到空 body？**
A: 抖音 web 接口对无 cookie 的请求在 IP/环境层面全面风控，无论是否带 a_bogus 签名。这是平台硬门槛。

**Q: cookie 多久失效？**
A: 通常几小时到几天，失效后 `aweme/post` 会返空 body。重新按第 1 步复制一份即可。

**Q: 有没有完全免登录的办法？**
A: 批量回捞用户作品列表目前没有可靠免登录办法。开源工具能"批量下载"也是靠用户注入自己的登录 cookie。
