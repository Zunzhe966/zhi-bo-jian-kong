## 二、抖音监控完整链路（已破解）

### 1. 支持的输入格式（前端帮助文字明确）
```
1、主播的【抖音号】【推荐】: xxxx            → 例 xiguahochi96
2、APP分享链接: https://v.douyin.com/xxxxx
3、PC直播页链接: https://live.douyin.com/xxxx
4、PC主页链接: https://www.douyin.com/user/xxxx
```

### 2. 前端调用链（明文 JS 还原）
```
用户输入(停止1秒后) → ipcRenderer.send("resolveChannel", {inputStr, platform:"DouYin"})
                    → 主进程 resolveChannel 处理
                    → 返回 {providerId, channelId, owner}
                    → 前端回填表单 channelId + remarks
```

### 3. 核心接口（从 index.jsc 字符串提取）
```
# 查询直播间信息（核心，用 sec_user_id）
https://webcast.amemv.com/webcast/room/reflow/info/?type_id=0&live_id=1&sec_user_id={sec_uid}&X-Bogus={签名}
# 直播间进入接口
https://live.douyin.com/webcast/room/web/enter/
# 分享短链跳转目标
iesdouyin.com/share/user
# URL解析正则
^(?:http[s]?:\/\/)?(?:[a-zA-Z0-9-]+\.)?douyin\.com\/(?:user\/|live\/)?(.+)$
```

### 4. 签名机制
- 请求必须带 **`X-Bogus` / `a_bogus`** 签名参数（V8 字节码里的核心算法）
- 签名基于 `sec_uid + 设备指纹(webid/uifid/verifyFp/fp) + 时间戳` 计算
- 签名算法受保护，但**用真实浏览器驱动可自动生成，无需破解算法本身**

## 四、关键瓶颈：抖音号 → sec_uid 转换

这是**唯一尚未绕过签名也能解决的难点**，实测结论：

| 方法 | 结果 |
|------|------|
| 直接访问 `/user/{抖音号}` | ❌ profile接口返回 "UserId不合法"（抖音号≠sec_uid） |
| 搜索接口 `/aweme/v1/web/general/search/` | ❌ 需要登录（status 2483 请先登录） |
| iesdouyin/share/user 短链 | ❌ 返回 200 但无法直接解析出 sec_uid |
| **真实浏览器站内搜索** | ⚠️ 未登录访客态仍被拦截 |

**结论**：抖音号→sec_uid 的转换，备份软件也是靠**真实浏览器访问 + 可能的登录态**实现（其核心算法在加密字节码里）。当前最可行的替代方案：
1. **用户在抖音 App 复制分享链接** `v.douyin.com/xxx`（分享链接 302 跳转后 URL 里带 sec_uid）
2. **用真实浏览器驱动打开** `www.douyin.com/user/{抖音号}`，配合登录态可搜出 sec_uid

## 六、对项目（尊者监控直播短视频）的落地建议

1. **新增"抖音分享链接解析"**：接受 `v.douyin.com/xxx`，用系统 Chrome 驱动跳转拿 sec_uid（与备份软件一致）
