# 尊者直播监控 —— 打包与发布操作手册

> 本文档说明如何把本项目从「源码」打包成一个**可分发的软件**（macOS 的 .app/.dmg、Windows 的便携版 .exe），以及如何发布给他人使用。
>
> 适用对象：需要构建/分发软件的用户。**普通使用软件的人不需要读本文档**，直接运行打包产物即可。

---

## 0. 一句话说明

本项目 = **Electron 桌面界面** + **Rust 后台 daemon** + **ffmpeg 录制引擎** + **配置文件**。
打包就是把这一整套东西装进一个"软件外壳"里，让用户双击就能用，**不需要装 Python / Node / Rust**。

打包产物（本机已产出）：
- **macOS**：`desktop/release/尊者直播监控-<版本>-arm64.dmg`（安装包，约 144MB）
- **macOS**：`desktop/release/mac-arm64/尊者直播监控.app`（应用目录）
- **Windows**：在 Windows 机器上运行 `build.bat` 后产出的便携版 `.exe`

---

## 1. 打包范围（软件里装了什么）

| 组件 | 来源 | 打包后位置 | 作用 |
|------|------|-----------|------|
| Electron 桌面 UI | `desktop/`（vite 构建的 `dist/`） | `Contents/Resources/app.asar` | 图形界面 |
| Rust daemon | `zunzhe-core/target/release/zunzhe-core` | `Contents/Resources/bin/zunzhe-core` | 后台核心（监控/录制/复盘调度） |
| ffmpeg | `ffmpeg/ffmpeg` | `Contents/Resources/ffmpeg/ffmpeg` | 直播录制/视频下载引擎 |
| 默认配置 | `config/` | `Contents/Resources/config/` | 首次运行的默认配置模板 |

**首次运行时**（由 `desktop/electron/main.cjs` 的 `ensureRuntime()` 完成）：
1. 在系统用户数据目录（macOS: `~/Library/Application Support/尊者直播监控/`）创建 `config`、`logs`、`downloads`、`recordings`、`fupan_output`、`rsshub` 等目录
2. 把 `Resources/config/` 里的默认配置复制过去（已存在的不会被覆盖，保护用户改动）
3. 把 `Resources/ffmpeg/ffmpeg` 复制到用户目录的 `ffmpeg/`（daemon 的 `find_binary` 只认这个位置）

> **重要**：用户的所有数据（配置、录制的视频、复盘结果）都存在**用户数据目录**，不在 .app 里，所以升级软件不会丢数据。

## 2. 前置条件（打包的机器需要）

| 工具 | 版本要求 | 安装方式 |
|------|---------|---------|
| Rust / Cargo | 1.70+ | https://rustup.rs |
| Node.js | 18+（建议 20/22） | https://nodejs.org |
| ffmpeg | 任意较新版本 | macOS: `brew install ffmpeg`；Windows: 下载后放入 `ffmpeg/` |
| desktop 依赖 | - | `cd desktop && npm install` |

## 3. macOS 打包（在 macOS 上执行）

### 3.1 一键打包

```bash
# 在项目根目录执行
bash scripts/build-package.sh
```

脚本会依次：
1. 校验 `ffmpeg/ffmpeg` 存在
2. 编译 Rust daemon（`cargo build --release`）
3. 构建前端 UI（`vite build`）
4. 清理旧产物
5. 用 electron-builder 打包 macOS .app

### 3.2 打包 DMG 安装包

```bash
bash scripts/build-package.sh --dmg
```

会额外生成可双击安装的 `.dmg`（文件名里的版本取自 `desktop/package.json` 的
`version`，**不是文本文档里写死的值**——查当前版本请读那个字段）。

### 3.3 跳过 Rust 编译（改 UI 时快速重打包）

```bash
bash scripts/build-package.sh --skip-rust --dmg
```

### 3.4 产物验证

打包完成后建议做一次"干净运行验证"：

```bash
# 直接运行打包的 daemon，确认它能读配置、返回状态
"desktop/release/mac-arm64/尊者直播监控.app/Contents/Resources/bin/zunzhe-core" status
```

返回 `{"ok":true,...}` 即正常。

## 4. Windows 打包（在 Windows 机器上执行）

> **注意**：Windows 便携版**必须在 Windows 机器上**打包。Rust 和 electron-builder 都不支持跨平台交叉打包。

1. 安装 Rust 与 Node.js
2. 把 `ffmpeg.exe` 放入项目根 `ffmpeg/ffmpeg.exe`
3. 执行 `cd desktop && npm install`
4. 回到项目根，**双击 `build.bat`** 或在命令行执行 `build.bat`

产物：`desktop\release\尊者直播监控-<版本>-便携版.exe`（免安装，双击即用）。

## 5. 常见问题（FAQ）

### Q1: 打包报 `bad option` 或 `SAFE_DELETE_BULK_GUARD_ERROR`？
这是**开发助手环境**（如 WorkBuddy/Codebuddy）注入的 safe-delete 拦截导致的，不影响代码。
打包脚本里已内置处理（清除 `CODEBUDDY_SESSION_ID` 等变量让拦截失效）。
**在干净的终端/普通用户机器上不会遇到此问题。**

### Q2: 打包的 .app 打不开，提示"已损坏"或"无法验证开发者"？
未签名（ad-hoc）应用第一次运行时 macOS 可能拦截。解决：
- 右键点击 .app →「打开」（而非双击），或
- 在终端执行：`xattr -dr com.apple.quarantine "尊者直播监控.app"`

### Q3: 我想发布给正式用户，怎么做才不会有"未知开发者"警告？
需要申请 **Apple 开发者证书**（Developer ID Application，$99/年）并配置签名。在 `desktop/package.json` 的 `build.mac` 增加 `"identity": "Developer ID Application: 你的名字"`。分发前用 `codesign` 签名 + `notarytool` 公证。

### Q4: 升级软件后，用户配置会丢吗？
不会。用户配置/数据存在**用户数据目录**（不在 .app 内），升级软件只是替换 .app，用户数据目录保持不变。

### Q5: 打包产物里有 `bin/zunzhe-core` 吗？
有。它位于 `Contents/Resources/bin/zunzhe-core`（macOS）或 `Resources/bin/zunzhe-core.exe`（Windows），是后台核心，Electron 启动时自动调用它。

## 6. 仓库位置与运行位置

> ⚠️ **本节曾写「Desktop 与 Projects 双副本」，已作废**（2026-09-22 更正）。
> `~/Desktop/尊者监控直播短视频` **已不存在**，`~/Projects/尊者监控直播短视频`
> 若存在也只是指向外置盘真实仓库的**符号链接**，不是第二份副本。

**唯一事实源是物理项目根**：`/Volumes/A区/尊者监控直播短视频`。

- **只有一个副本**，不要 `cp` 到别处"同步"——那会立刻造成两个版本。
- launchd plist 里钉的是**物理路径**（安装时用 `os.path.realpath` 解析过），
  不是符号链接路径。所以「改了 `~/Projects/...` 但 daemon 不生效」通常是因为
  那里只是个链接，改的其实是同一个文件；真正不生效请先跑
  `bash scripts/audit-launchd-log-paths.sh` 与 `zunzhe-core doctor` 确认。
- 装机脚本与仓库脚本必须一致：`~/Library/LaunchAgents/zunzhe-daemon.sh`
  应与 `scripts/start-rust-daemon.sh` 行为对齐（发现分叉时以仓库版为准回灌）。
