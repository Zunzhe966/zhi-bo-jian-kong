# 尊者直播监控 Rust 重构 — 目标模式（北极星）

> 本文件是 Rust 重构的恢复锚点。任何会话开始、上下文丢失、目标被压缩时，
> 先读本文件 + 项目根 `PROJECT_GOAL.md` + `git status`，再按“当前阶段”继续。

## 一、最终目标（验收标准）

1. **长期稳定可用**：`zunzhe-core` 可 24 小时 × 30 天持续运行，不崩溃、
   不丢状态、崩溃后重启自恢复（SQLite 持久化 + 任务队列重放 + 日志）。
2. **原子模块化**：每个最小功能是一个独立 crate 模块（config / model / db /
   platform / video_library / download / notify / pipeline_bridge / scheduler /
   training_data / cli），模块间只通过公开 trait + 结构体契约连接，像电话线一样
   可插拔、可单测、可替换。
3. **改动不破坏**：任何模块改动都必须先跑全量回归（`cargo test` + 集成测试），
   已验收功能回归失败 = 不允许提交。
4. **能力对齐**：Rust 逐个重写旧 Python 能力：直播监控/录制调度、发布视频监控、
   历史视频浏览与选择性下载、转写/提炼/切片复盘桥接、邮箱通知、视频库、训练数据
   JSONL、CLI/MCP 命令集。
5. **平台**：macOS 优先可用，Windows/Linux 可编译运行，未来可上云服务器。
6. **简单可用**：个人用户不用懂内部实现，桌面端/CLI 一键操作；不出现
   “用着用着崩溃”“监控断了没人管”“状态丢失”等基础稳定性问题。

## 三、接口契约（冻结）

- CLI 每条命令输出一行 JSON，命令名与 Python 版一致：
  `status / add-live / remove-live / list-live / check-live / add-video /
  remove-video / list-video / check-videos / download-video / blogger-videos /
  video-library / export-training-data / email-status / email-setup /
  test-email / start / stop / notes / process`
- SQLite 表：`anchors / videos / notify / tasks`，字段与 Python `video_library.py`
  对齐，`videos.downloaded` 是唯一“已下载”事实源。
- 平台适配器返回统一 `VideoMeta { id, platform, url, title, cover,
  published_at, duration }`，不泄漏平台私有字段。
- 复盘桥接通过子进程调用 Python 工具层（faster-whisper / LLM / ffmpeg），
  Rust 只负责调度、状态、通知与产物索引。

## 四、防回归规则（每次改动必须）

1. `cd zunzhe-core && cargo fmt --check && cargo clippy --all-targets && cargo test`
2. 新增模块必须带 `#[cfg(test)]` 单测；涉及跨模块的加集成测试。
3. 全量回归通过后才 `git add` / commit；commit 信息注明模块（如 `feat(zunzhe-core): M1 config`）。
4. 不允许把已验收模块“顺手改坏”：若修改共用接口，先更新契约文档再实现，
   并跑全量测试。

## 五、稳定性验收（24×30）

- daemon 循环用 `tokio::select!`，任何单个任务 panic 不拖垮主循环；
  顶层安装 panic hook + 崩溃日志；直播检查与视频检查各自独立任务，
  `JoinError` 只记日志，主循环继续下一轮。
- SQLite 每次写操作事务化；崩溃后重启读取 DB 恢复主播/视频/任务/通知状态。
- 服务守护：发现进程不在则拉起（launchd KeepAlive / 桌面端 watchdog）；
  日志轮转（保留 5 份）；心跳文件 30 分钟内必须刷新，否则 `status` 判为
  不健康；磁盘满/ffmpeg 缺失等通过 `doctor` 可诊断。
- 冒烟测试：`run-daemon --once` 与 `run-daemon --duration 30s` 不崩；
  `SIGTERM/SIGINT` 优雅退出并清理 pid 文件；长期稳定性由真实机器持续运行验收。

## 六、当前进度

M0-M17 已完成，通过 `cargo test` 全量回归（50 单测 + 4 集成契约测试）、`cargo fmt --check`、
`cargo clippy --all-targets` 与端到端冒烟（status/doctor/run-daemon/崩溃恢复/MCP 握手/mcp-info）。
M13 交付物：`scripts/start-rust-daemon.sh`（release 构建 + 常驻运行）、
`scripts/launchd/com.zunzhe.monitor.plist`（macOS 开机自启）、使用说明 Rust 章节、
`PROJECT_GOAL.md` 阶段表。

视频监控已对齐 Python 旧版首轮基线语义：首次检查某位博主只记录已有视频，不通知、
不下载；后续轮次只对新视频通知/下载。后续长期稳定性由真实机器持续运行验收；
平台风控（B站 412 / RSSHub 403）需要在配置中填入平台 Cookie 后重试，
Rust 适配器会返回明确错误而不是静默失败。

直播监控 M17：Rust daemon 已接管直播检测与 ffmpeg 录制，支持 B站原生
（room_init + playUrl/getRoomPlayInfo）和自定义 m3u8/flv 流地址；录制会话写
SQLite（live_sessions），崩溃重启后可恢复；录制结束后自动调用 Python 复盘流水线。
`start`/`stop` 兼容层在 Rust daemon 运行时不重复启动 Python 直播服务，避免双录；
`stop` 只停 Rust daemon 与录制进程，不自动拉起 Python 服务（避免“停止”反而启动服务）。

稳定性加固：所有平台适配器/直播检测请求统一 20 秒超时；daemon 每轮 tick
直播检查与视频检查并行、整体最多 70 秒，超时强制 abort 本轮子任务再进入下一轮，
避免上一轮子任务残留导致重复检查/下载；`--duration N` 用独立 watch 通道按时退出，
不会因单次网络阻塞而无限运行。

新增稳定性修复（已通过 37 个测试 + fmt + clippy）：
- 手动录制 `record-live` 增加 Ctrl-C/SIGTERM 清理：ffmpeg 独立进程组，
  中断时按组终止并删除 pid 文件，避免孤儿录制进程。
- yt-dlp 下载与 Python 复盘子进程增加超时（下载 10 分钟、复盘 60 分钟），
  超时自动终止并返回明确错误，不让 daemon 无限挂起。
- 下载任务失败重试第 3 次即标记 failed，不再无限卡在 pending 队列。
- `stop` 先停 Rust daemon 再尽力拉起 Python 兜底：兜底失败不再导致“停不掉”。
- 进程存活检查按平台实现：Windows 用 tasklist，不再硬编码 /proc。
- yt-dlp 查找以项目根 `.venv` 为基准，跨目录运行也不依赖当前工作目录。
- B站视频监控链路加固：单源检查超时 50 秒、yt-dlp 兜底 30 秒、view 接口校验
  `code=0`，无效 BV 不再写入视频库；真实环境匿名访问 B站会 352/412 风控，
  需要配置 `b站cookie` 后恢复。
- 服务语义修正：`start` 只启动 Rust daemon，不再并行启动 Python 视频监控，
  避免同一批视频源被两套逻辑重复检查/通知/下载；`stop` 只停 Rust daemon 与
  录制进程，不自动拉起 Python，用户点“停止”不会反而启动服务。
- 调度器只检查 `视频监控列表.ini` 的源，不再把直播主播误当成视频源去拉取。

新增稳定性交付（已通过 37 个测试 + fmt + clippy，二进制抽成 lib 可测试）：
- `binary → lib`：`src/lib.rs` 导出全部模块，主程序只负责参数/日志/panic hook，
  集成测试可跨模块验证 daemon。
- daemon 心跳：每轮 tick 前刷新 `fupan_output/run/zunzhe-core.heartbeat`；
  `status.rust_daemon` 只有在进程存活且心跳 30 分钟内刷新时才为 true，
  避免“进程在但调度僵死”的假健康。
- daemon 优雅退出：`SIGTERM/SIGINT`、`--duration` 到点都会先停录制、
  清理 pid 文件再退出；`run-daemon --once` 同样清理 pid。
- `doctor` 命令：输出守护心跳、日志/运行目录可写、ffmpeg 位置、磁盘剩余 MB，
  供桌面端/CLI 一键诊断。
- 启动脚本每次构建 release 后常驻，不再使用可能过期的旧二进制；
  `start`/`ensure-services` 把 daemon 输出写入 `logs/zunzhe-core.log` 并轮转。

新增稳定性交付（已通过 37 个测试 + fmt + clippy + release 构建）：
- 下载队列去重：同一 `kind+url` 已有 `pending/failed` 任务时不再重复入队，
  返回已有任务 id；daemon 多轮重试不会堆积同一视频的下载任务。
- daemon tick 超时护栏修正：70 秒超时后 abort 直播/视频检查两个子任务并等待
  收尾，保证下一轮开始前上一轮任务一定结束，不产生并发重复检查/下载。

新增稳定性交付（已通过 39 个测试 + 3 集成契约测试 + fmt + clippy + release 构建）：
- daemon 单实例锁：`fupan_output/run/zunzhe-core.lock` 用独占文件锁贯穿整个
  daemon 生命周期，重复 `run-daemon` 直接报错退出；pid 文件只由锁持有者
  写入/清理，第二实例不会误删第一实例的 pid。
- 启动竞态加固：`start_rust_daemon` 不再由父进程预写 pid，而是等 daemon
  自己拿到锁、写好 pid+心跳后确认健康；锁被占用但心跳不新鲜时先停旧进程
  再拉起，watchdog 能恢复“假健康/僵死 daemon”。

新增稳定性交付（已通过 41 个测试 + 3 集成契约测试 + fmt + clippy + release 构建）：
- SQLite 统一连接：WAL + busy_timeout 15 秒 + foreign_keys，daemon 多任务
  并发读写不再频繁锁库；生产/CLI/MCP 共用 `db::open_pool` 单一入口。
- 录制会话防覆盖：daemon 停止后后台 ffmpeg 收尾先确认会话仍为 recording，
  已 stopped 的会话不会被迟到的 failed/done 覆盖，也不在主动停止后误跑复盘。
- 下载任务崩溃恢复：任务先原子认领为 processing 再执行，崩溃遗留任务在下一轮
  tick 自动归还 pending 重试，避免队列永久卡死或并发重复下载。

新增稳定性交付（已通过 44 个测试 + 3 集成契约测试 + fmt + clippy + release 构建）：
- SMTP 通知异步化：阻塞发信放到 blocking 线程池并限时 20 秒，失败/超时保留
  pending 记录；daemon 每轮 tick 重试 pending 通知，邮件临时故障不会丢通知，
  也不会卡死监控轮次。

- `--duration` 按时退出：duration 到点会中断当前 tick 并清理 pid/录制进程，
  不再等到整轮 70 秒网络超时结束后才退出。
