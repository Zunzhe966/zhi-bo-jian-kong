## 1. 改了什么

### 1.1 核心：把「程序目录」和「产物目录」拆开

这是整个改造的支点。之前一个 `project_dir` 同时承担两个角色，所以「改产物位置」和「把程序搬走」被绑在一起，谁都不敢动。

现在分成两个根：

- **项目目录**（`project_dir`）：程序与配置所在。`config/`、`.venv/`、`src/`、`fupan/`、`zunzhe-core` 二进制。由 `config::find_project_root` 往上找 `config/config.ini` 决定，**不开放给用户改**（改了 daemon 立刻找不到配置和 Python 环境）。
- **产物根目录**（`media_root`）：程序跑出来的东西。下载的短视频、转写文本、知识点、精华切片、封面、直播录像、运行态文件。由 `[路径设置] 产物根目录` 决定，**留空时等于项目目录**，即完全保持旧行为。

### 1.2 Rust 侧：新增 `zunzhe-core/src/paths.rs`

单一真相来源。对外只暴露几个函数，调用方拿到的永远是解析好的绝对路径：

```
paths::storage(project_dir)     -> Arc<StoragePaths>   // 全量，带缓存
paths::media_root(project_dir)  -> PathBuf
paths::downloads(project_dir)   -> PathBuf
paths::fupan(project_dir)       -> PathBuf
paths::covers(project_dir)      -> PathBuf
paths::run_dir(project_dir)     -> PathBuf
paths::database(project_dir)    -> PathBuf
paths::ensure_dirs(project_dir) -> io::Result<()>      // 建齐目录，启动时调一次
paths::trusted_media_roots(project_dir) -> Vec<PathBuf>
paths::is_trusted_media_path(project_dir, file) -> bool
paths::canonical_lenient(path)  -> PathBuf
```

两个设计决定值得说明：

1. **解析永不失败。** 读不到配置、路径非法、家目录取不到，统统退回默认布局。路径解析一旦能失败，就会被调用方 `?` 成「监控整个挂了」——一个存储路径配错不该让 daemon 起不来。
2. **只读 `config/config.ini`，不走 `Config::load`。** 这一条是踩出来的：`Config::load` 会连带读 `fupan_config.ini`，读不到就直接整体报错，导致产物路径被静默忽略、全部退回默认。一个「复盘参数文件缺失」不该让用户的存放位置配置凭空失效。现在依赖收窄到只跟路径有关的那个文件。

缓存按「项目目录 + `config.ini` 的 (mtime, 长度)」做键。daemon 每轮 tick 都重读配置（`Watchlist::new(project_dir)` 就是这机制），用户改完配置不重启即生效，每次调用只多一次 `stat`。

### 1.3 Rust 侧：替换了 29 处写死调用点

`downloads` / `fupan_output` 的拼接全部改成 `paths::` 调用，共 34 个调用点，覆盖 14 个文件：

`bilibili_auth.rs` `bilibili_electron.rs` `cli.rs` `config.rs` `daemon_lock.rs` `db.rs` `download.rs` `live_monitor.rs` `mcp.rs` `notify.rs` `platform.rs` `scheduler.rs` `service.rs` `status_snapshot.rs`

替换只在**非测试代码**里做（用括号配对扫描精确排除 `#[cfg(test)]` 块，跳过字符串/字符/注释）。测试区一行未动。

新增 CLI 命令 `zunzhe-core paths`，输出解析后的全部目录，供桌面端和脚本查询。它刻意早于数据库/目录创建返回——桌面端在数据库还没建、或产物目录暂时不可写时，也要能问出「文件到底存哪」。

### 1.4 Rust 侧：三处连带修复

1. **复盘入队白名单**（`download.rs::enqueue_process`）。原来只认 `<项目根>/downloads` 与 `<项目根>/fupan_output`，后果是：用户一旦把产物搬走、或在「直播保存路径」填了自定义目录，**录完的直播会被这条校验悄悄拒掉，永远进不了复盘**。现在可信根跟着配置走，默认布局下的边界与改动前完全一致（没有因为「可配置」而放宽）。
2. **历史任务路径改写**（`db.rs::rewrite_legacy_task_paths`）。原来把 `~/Desktop/.../downloads/x.mp4` 一律拼到项目根。产物根改到别处后，那样改写出来的是一条不存在的旧位置，比不改还糟。现在 `downloads/`、`fupan_output/` 两段前缀按当前配置重定位。
3. **状态快照的 `recordings` 字段**（`status_snapshot.rs`）。原来等于 `downloads`，现在等于「直播保存路径」解析结果——界面「打开录制目录」必须开真正的录像目录。

### 1.5 Python 侧：`fupan/settings.py` 增加同构解析

`storage_paths()` 返回与 Rust 完全一致的字典，模块级常量 `FUPAN_DIR` / `DOWNLOADS_DIR` / `RUN_DIR` / `RECORDINGS_DIR` 全部由它推导，不再是写死路径。

这是必须的：两边都写同一批目录，一旦算法不同（`~` 展开规则、相对路径基准），daemon 写到 A、复盘去 B 读，就会出现「明明录完了却找不到文件」这类静默错位。

连带改动：
- `fupan/video_monitor.py`：`VIDEO_DOWNLOAD_ROOT` 跟随产物根（否则下载/查重/去重全指向一个已不存在的老目录）
- `fupan/bili_browser.py`：`RUN_DIR` 跟随
- `fupan/cli.py`：`status()` 的录像扫描改用真实录像目录；`file` 字段加 `ValueError` 兜底——录像落在项目之外时 `relative_to(PROJECT_DIR)` 会抛异常把整个 `status` 命令带崩
- `main.py`：`default_path` 改为读 `[路径设置]`（遗留 Python 录制器，已无脚本引用，但写死就该一并清掉）
- `scripts/douyin_fetch.py`：默认输出目录跟随产物根（`--output` 仍优先）

### 1.6 Electron 侧：`desktop/electron/main.cjs`

**数据目录不再写死。** 旧代码把 `DATA_DIR` 硬编码成 `~/Projects/尊者监控直播短视频`，后果是：这个 `.app` 只在本机可用、换机换盘就废，且用户没有任何办法把它指到别处。现在按优先级解析：

1. 环境变量 `ZUNZHE_PROJECT_DIR`
2. `<userData>/数据目录.txt` 的第一行（托盘菜单「选择数据目录…」写入）
3. 自动探测：`~/Projects/…`、`~/Desktop/…`、`/Volumes/*/…`
4. `app.getPath('userData')`（首次运行兜底）

托盘中新增两项：**「选择数据目录…」**（系统目录选择器 + 写指针文件 + 自动重启）和**「打开数据目录」**。

**「打开目录」按钮不再静默失效。** 白名单原来是 `[应用包目录, userData]`，而界面要打开的路径是 `~/Projects/…` → 不在白名单 → handler 返回一个字符串、渲染层又不看返回值 → 点了没反应、连报错都没有。现在启动时向核心问一次 `zunzhe-core paths`，把真实产物目录全部纳入白名单；配置一改就刷新。另外：

- 目录还没建（产物根刚改完、还没跑过一轮）时，退到「仍在白名单内、且真实存在的最近祖先」，而不是直接拒绝
- 真打不开时留日志 + 发一条系统通知，让失败可被看见
- 通知队列路径改为读核心上报的 `run` 目录（用户搬走产物后，界面原本会永远读不到通知）

### 1.7 新增文件 `desktop/electron/path-utils.cjs` + 单测

把最容易出错、也最值得单测的路径判断从 `main.cjs` 抽出来（不依赖 `electron`，纯 Node 可测）。`path-utils.test.cjs` 有 29 个断言，含一个**回归用例**直接证明旧白名单会拒掉真实日志目录。

## 2. 新增的配置：`config.ini` 的 `[路径设置]`

已写入 `config/config.ini`、`config/config.ini.example`、`config-template/config.ini`。

```ini
[路径设置]
; 产物总根目录。留空 = 项目目录。
产物根目录 =
; 单独覆盖短视频下载落点。留空 = <产物根目录>/downloads
短视频下载目录 =
; 单独覆盖复盘输出落点（转写/知识点/切片/封面）。留空 = <产物根目录>/fupan_output
复盘输出目录 =
; SQLite 库文件。留空 = <项目目录>/zunzhe-core.db
数据库文件 =
```

路径写法三种都认：绝对路径、`~` 家目录、相对项目目录的相对路径。目录不存在会自动创建。

想建自己的专属文件夹，**只填「产物根目录」一项就够**，其余三项自动跟着走。例如：

```ini
产物根目录 = ~/Documents/尊者产物
```
