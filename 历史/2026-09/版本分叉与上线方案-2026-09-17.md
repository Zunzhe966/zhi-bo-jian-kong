我原本以为是「A 区新、Projects 旧，推过去就行」。查完发现不是。

A 区 HEAD = `170d5b2`，Projects HEAD = `9fde9d9`，**两者互不为祖先**（已用 `merge-base --is-ancestor` 验证）。
更要命的是：**两边的工作区里都有对方完全没有的代码**，且都还没提交
（A 区 110 个文件未提交，Projects 70 个）。

## 四、三个上线方案

### 方案 1（推荐）：先合，再推，A 区成为唯一真源

1. 把 Projects 独有的 3 处 UI 功能移植回 A 区（Rust 侧 `notify-list` 两边都有，所以主要是
   `App.jsx` / `PersonCards.jsx` 两文件 + `main.cjs` IPC 白名单补一条 `notify-list`）。
2. 在 A 区重新 `npm run build` 验证 UI。
3. A 区 → Projects 同步（此时是单向的，不再丢东西）。
4. 重建 Projects 侧 release 二进制，`launchctl kickstart` 重启 daemon。
5. 重新打包 `.app`（需要先退出正在跑的 GUI，PID 56567）。

- 收益：分叉消失，今天所有修复上线，打包版也是新的。
- 代价：工作量最大，要动 UI 代码和重打包。

### 方案 2：只做外科手术，把今天的纯修复打到 Projects

不碰 `paths.rs` 重构、不碰 UI、不碰抖音链，只把下面这些**纯修复**用逐处编辑的方式打到 Projects 上，
然后重建 release 二进制 + 重启 daemon：

- `main.py`：`run_script` 加超时 / 进程组独立 / 失败检查；`direct_download_stream` 加超时；
  3 处配置写入改原子写
- `src/utils.py`：新增 `atomic_write_text`
- `zunzhe-core/src/config.rs`：`video_check_interval_secs()`
- `zunzhe-core/src/scheduler.rs`：`检查间隔秒` 真正生效（原本是死配置）
- `zunzhe-core/src/platform.rs`：RSSHub/yt-dlp 失败不再天天刷 WARN
- `zunzhe-core/src/bilibili_electron.rs`：补 `ZUNZHE_RUN_DIR` 环境变量（这是 Electron 找不到 run 目录的根因）
- `desktop/electron/main.cjs`：IPC 命令白名单 + watchdog 不再自己拉起服务
- `desktop/electron/bili-cookie.cjs`：cookie 落点跟随运行目录

- 收益：快、风险低、立刻生效。
- 代价：「去写死」重构和抖音扫码登录**不上线**，UI 分叉继续存在。

### 方案 3：只重打包 .app，不动 daemon

只把 A 区的 UI + 二进制重新打成 `/Applications/尊者直播监控.app`。daemon 完全不动。
适合「先让桌面端变新，后台监控别动」。
