### 1.1 daemon 主日志无上限增长 —— 已修复，生效中

**改动文件**：`~/Library/LaunchAgents/zunzhe-healthcheck.sh`
**备份**：`~/Library/LaunchAgents/zunzhe-healthcheck.sh.bak-20260917-124835`

改前的 `rotate_if_large()` 用 `mv "$file" "$file.1"` 轮转。launchd 的 `StandardOutPath` 是把 fd 绑在 inode 上的，`mv` 只改目录项、不会让 launchd 重新 open，于是：

1. 第一次轮转把 `zunzhe-core.log` 改名成 `.log.1`，daemon 继续往这个 inode 写；
2. 之后每轮 `[ -f "$file" ]` 为假（因为 `zunzhe-core.log` 已经不存在了），**直接跳过**，再也不轮转；
3. 结果 daemon 7 天的日志全堆在 `zunzhe-core.log.1`，涨到 14.8MB 且没有上限。

**改后的函数**：

```bash
rotate_if_large() {
  local file="$1"
  local max_bytes="${2:-5242880}"
  local size
  if [ -f "$file" ]; then
    size="$(stat -f%z "$file" 2>/dev/null || stat -c%s "$file" 2>/dev/null || echo 0)"
  else
    size=0
  fi
  if [ "$size" -lt "$max_bytes" ]; then
    return 0
  fi
  # 归档档后移：这些文件没有进程持有 fd，mv 是安全的。保留 .1~.5 共 5 份。
  for i in 4 3 2 1; do
    if [ -f "$file.$i" ]; then
      mv -f "$file.$i" "$file.$((i+1))" 2>/dev/null || true
    fi
  done
  # live 文件：先快照成 .1，再原地截断。绝不能 mv，否则 daemon 的 fd 会跟着
  # 改名走，日志从此落到 .1 且永不轮转。
  cp -f "$file" "$file.1" 2>/dev/null || true
  : > "$file" 2>/dev/null || true
}
```

**关键区别**：live 文件用「复制 + 原地截断」，inode 不变，launchd 的 fd 继续有效；只有归档档（没有进程持有 fd）才用 `mv`。

**同时做的恢复**：把已经被改名走的 `.log.1`（14.8MB）改回 `zunzhe-core.log`。`mv` 不影响已打开的 fd，所以 daemon 没有中断。

**修复后实测**：

```

zunzhe-core.log.1     14,874,412    12:49（今天的归档快照）
zunzhe-core.log.3      8,163,201    09-10
zunzhe-core.log.4     18,164,781    09-05

```

现在每个日志文件上限 5MB × 6 份（live + .1~.5）= 单文件族最多约 30MB，不会再有无限增长。

#### 2.6 让「检查间隔秒」真正生效

**现状**：`config/fupan_config.ini` 写 `[视频监控] 检查间隔秒 = 900`，但 Rust 侧只在测试代码里出现这个键名（`config.rs:1024`、`config_api.rs:219`），调度器从不读。真实节拍 = `cli.rs:188-189` 的 `--interval`，默认 **60 秒**。

**代价（实测）**：B 站投稿接口每 60–70 秒被打一轮；最近 3000 行日志 `412` 出现 694 次、`352` 出现 166 次；`doctor` 报 `source_health: failing 2/4`。

为什么会一直打：每轮的四级兜底里，最后一级 yt-dlp 总能拿到 30 条 → 整轮算"成功" → 失败冷却（`scheduler.rs:909`，15 分钟起、上限 2 小时）被清零 → 下一轮又从第一级开始打 5 次请求。

**修法**：在 `scheduler.rs` 主循环里给视频检查做独立节流，让配置说了算：

```rust
// run_daemon 主循环外，读一次（每轮 tick 已会热重载 config，可放循环内）
let video_interval = current_config
    .get_fupan("视频监控", "检查间隔秒")
    .trim()
    .parse::<u64>()
    .unwrap_or(900)
    .max(60);                       // 兜底 60 秒，配置写坏了也不至于打爆
let mut last_video_check: i64 = 0;

// 主循环里，替换原先无条件跑视频检查的那一行
let now_ts = chrono::Local::now().timestamp();
if now_ts - last_video_check >= video_interval as i64 {
    last_video_check = now_ts;
    // ...原有视频监控检查逻辑...
}
```

这样直播监控仍然是 60 秒一轮（开播检测及时），视频监控按配置的 900 秒走，B 站接口压力降到 1/15。

（另一种选择是从界面和 `fupan_config.ini` 里直接删掉这一项。不推荐——用户会一直以为能调。）

    name: &str,

    let trusted = if media_path.is_absolute() {

fn contains_url(text: &str) -> bool {
    let t = text.trim().to_lowercase();
    if t.contains("://") || t.starts_with("www.") {
        return true;
    }
    // 裸域名：至少一个点 + 以已知平台后缀结尾（与 PLATFORM_ROUTES 对齐）
    const SUFFIXES: &[&str] = &[
        "bilibili.com", "douyin.com", "kuaishou.com", "huya.com", "douyu.com",
        "youtube.com", "youtu.be", "twitch.tv", "xiaohongshu.com", "zhihu.com",
    ];
    SUFFIXES.iter().any(|s| t.split('/').next().unwrap_or("").ends_with(s))
}
