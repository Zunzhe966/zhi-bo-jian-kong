### 3. 抖音短视频：之前**完全没有**在监控，而且线上和打包版根本没这个能力

这条要说清楚，分两层：

**第一层，配置层的实况：**

- `config/视频监控列表.ini`（视频源的唯一权威）里**一个抖音源都没有**，两份副本都只有 B站
- 数据库 `videos` 表 287 条里，B站 285 条、rss 只有 2 条 —— 那 2 条是 8/15 从 `rsshub.app/douyin/user/...` 拿的
- 那个 rsshub 抖音源在 `monitor_baseline` 里 `consecutive_fails = 2`、`last_failed_at = 2026-08-23 05:43:17` —— **8/23 起就一直失败**，之后也没人管
- `config/监控偏好.json` 里还挂着这个抖音订阅（名字叫「侯翠翠抖音」），属于僵尸条目

**第二层，能力层的实况（更要紧）：**

线上（`~/Projects`，也就是 launchd 真正跑的那份）的 Rust 源码里，抖音短视频适配器**一行都没有**：

```
$ grep -cE "DouyinAdapter|douyin" ~/Projects/尊者监控直播短视频/zunzhe-core/src/platform.rs

$ ls ~/Projects/尊者监控直播短视频/desktop/electron/ | grep -i douyin
```

也就是说：**不只是没配源，是线上那份根本没有能力。** 抖音短视频需要三个部件凑齐 —— Rust 的 `DouyinAdapter`、Electron 的 `douyin-video-list.cjs`、还有登录态 Cookie —— 这三样只存在于 A 区工作副本，从没编译上线，也从没打进 `.app`。

**还需要的两步（都只有你能做）：**

## 四、这轮新发现（上一份清单里没有的）

1. **`自定义脚本执行命令` 也是一个死配置。** Rust daemon 跑复盘时直接调 `<.venv>/bin/python -m fupan.pipeline`，**完全不读这一项**。它只对旧的 Python 录制路径（`main.py`）生效。所以那个「打包版复盘不产出」的老问题，根因不只是 .app 里没 Python 层，还叠加了「这项配置对 Rust 完全不生效」。已在注释里标注。

2. **`bili-cookie.cjs` 和 `douyin-cookie.cjs` 的修复程度本来不一致。** 抖音那个之前已经支持 `ZUNZHE_PROJECT_ROOT` 环境变量，B站那个是纯 `__dirname`。现在两者统一为同一套三级解析。

3. **macOS 上 `osascript ... Finder delete` 会被 TCC 拦。** 报 `权限违例 (-10004)`。改用 `/usr/bin/trash` 成功。需要说明的是：工具沙箱不允许我列目录确认废纸篓内容（`~/.Trash` 和 `/Volumes/A区/.Trashes` 都是 Operation not permitted），所以这 5 个文件我是按「已在废纸篓可恢复」处理的，但没能亲眼在废纸篓里点出来。
